## Overview

The Artifacts Workspace API enables you to create AI-powered workspaces with:
- **JWT Authentication** - Secure user registration, login, and token management
- **Intelligent Chat** - Stream AI responses with tool execution
- **File Search** - Semantic search across uploaded documents
- **URL Fetching** - AI can read and analyze webpages with pagination
- **Graph Artifacts** - Create and manage mind maps and concept graphs
- **Real-time Events** - SSE streaming for live updates

## Base URL

```
http://localhost:8000
```

## Authentication

The API uses JWT (JSON Web Tokens) for authentication:
- **Access tokens** expire after 6 hours
- **Refresh tokens** expire after 7 days
- Protected endpoints require `Authorization: Bearer <access_token>` header

<Note>
All endpoints return JSON except SSE streams which return `text/event-stream`.
</Note>

Register a new user account.

<ParamField body="email" type="string" required>

<ParamField body="password" type="string" required>

```bash cURL
  -H "Content-Type: application/json" \
```

```javascript JavaScript

        password: "securepassword123"

});
const {access_token, refresh_token} = await response.json();
```
</RequestExample>

<ResponseExample>

# Chat

Stream AI responses with support for file search, URL fetching, and tool execution.

## Stream chat

<ParamField path="workspace_id" type="string" required>
  Workspace ID
</ParamField>

<ParamField body="message" type="string" required>
  User message for the AI (1+ characters)
</ParamField>

<ParamField body="url" type="string">
  Optional URL for AI to fetch and analyze
</ParamField>

<ParamField body="enable_file_search" type="boolean" default={true}>
  Enable semantic search in workspace vector stores
</ParamField>

<ParamField body="max_file_search_results" type="integer">
  Maximum number of file search results to retrieve
</ParamField>

<ParamField body="include_file_search_results" type="boolean" default={false}>
  Include raw file search results in SSE stream
</ParamField>

<ParamField body="force_web_search" type="boolean" default={false}>
  Force AI to use web search for current information
</ParamField>

<RequestExample>
```bash cURL
curl -N -X POST http://localhost:8000/workspaces/{workspace_id}/chat \
  -H "Content-Type: application/json" \
  -d '{
    "message": "What are the key findings in the research paper?",
    "enable_file_search": true
  }'
```

```python Python
import requests

response = requests.post(
    f"http://localhost:8000/workspaces/{workspace_id}/chat",
    json={
        "message": "What are the key findings?",
        "enable_file_search": True
    },
    stream=True
)

for line in response.iter_lines():
    if line:
        print(line.decode())
```

```javascript JavaScript
const response = await fetch(
    `http://localhost:8000/workspaces/${workspaceId}/chat`,
    {
        method: "POST",
        headers: {"Content-Type": "application/json"},
        body: JSON.stringify({
            message: "What are the key findings?",
            enable_file_search: true
        })
    }
);

const reader = response.body.getReader();
const decoder = new TextDecoder();

while (true) {
    const {done, value} = await reader.read();
    if (done) break;
    console.log(decoder.decode(value));
}
```
</RequestExample>

<RequestExample>
```bash cURL
curl -N -X POST http://localhost:8000/workspaces/{workspace_id}/chat \
  -H "Content-Type: application/json" \
  -d '{
    "message": "Can you expand on agriculture? Add nodes for crop types, livestock systems, and soil management"
  }'
```

```python Python
response = requests.post(
    f"http://localhost:8000/workspaces/{workspace_id}/chat",
    json={
        "message": "Expand on the transportation node with different vehicle types"
    },
    stream=True
)
```

```javascript JavaScript
const response = await fetch(
    `http://localhost:8000/workspaces/${workspaceId}/chat`,
    {
        method: "POST",
        headers: {"Content-Type": "application/json"},
        body: JSON.stringify({
            message: "Can you add more detail to the renewable energy section?"
        })
    }
);
```
</RequestExample>

<ResponseExample>
```text SSE Stream
event: tool_call
data: {"type":"tool_call","tool_name":"list_graphs","tool_call_id":"call_1"}

event: tool_call
data: {"type":"tool_call","tool_name":"add_node","tool_call_id":"call_2","arguments":{"artifact_id":"abc123","id":"ag_crop_types","label":"Crop types","level":3}}

event: tool_call
data: {"type":"tool_call","tool_name":"add_node","tool_call_id":"call_3","arguments":{"artifact_id":"abc123","id":"ag_cereals","label":"Cereals and grains","level":4}}

event: tool_call
data: {"type":"tool_call","tool_name":"add_edge","tool_call_id":"call_4","arguments":{"artifact_id":"abc123","source":"agriculture","target":"ag_crop_types","relationship_type":"contains"}}

event: content
data: {"type":"content","content":"Expanded the Agriculture node by adding 3 main categories with 15 detailed sub-nodes..."}

event: done
data: {"type":"done"}
```
</ResponseExample>

<Note>
When you ask to expand a node, the AI will:
1. Find the existing graph using `list_graphs()`
2. Add new child nodes or related nodes to the specified topic
3. Create appropriate edges (hierarchical or cross-level)
4. Return both the updated graph structure and a summary

This allows iterative graph refinement - start broad, then drill into specific areas.
</Note>

<Warning>
The AI will **modify the graph structure**, not just provide text explanations. To get text-only explanations of nodes or edges without modifying the graph, use the [explain-node](#explain-node-streaming) or [explain-edge](#explain-edge-streaming) endpoints.
</Warning>

# File Search

Enable semantic search across workspace documents using OpenAI's vector stores.

## Overview

File search allows the AI to retrieve relevant information from uploaded documents:

1. Create a vector store in your workspace
2. Upload files (PDF, DOCX, TXT, code files, etc.)
3. Enable file search in chat (enabled by default)
4. AI automatically searches and cites documents

<Note>
File search is automatically enabled when a workspace has vector stores with files.
</Note>

## Supported file types

| Format | MIME Type | Max Size |
|--------|-----------|----------|
| .txt | text/plain | 512MB |
| .md | text/markdown | 512MB |
| .pdf | application/pdf | 512MB |
| .doc, .docx | application/msword | 512MB |
| .html | text/html | 512MB |
| .json | application/json | 512MB |
| .py, .js, .ts | Code files | 512MB |
| .java, .cpp, .c | Code files | 512MB |
| .go, .rb, .php | Code files | 512MB |
| .pptx | PowerPoint | 512MB |

<Warning>
Text files must be UTF-8, UTF-16, or ASCII encoded.
</Warning>

# Artifacts

Artifacts store graph data (mind maps, concept maps, etc.) in JSON format.

## Data model

Artifacts use `application/vnd.graph+json` MIME type with this structure:

<ResponseField name="graph_type" type="string">
  Graph type: `mind_map`, `concept_map`, `causal_loop`, `systems_thinking`
</ResponseField>

<ResponseField name="nodes" type="array">
  List of graph nodes
</ResponseField>

<Expandable title="nodes[]">
  <ResponseField name="id" type="string">Descriptive node ID (e.g., 'central_ai', 'core_nlp')</ResponseField>
  <ResponseField name="label" type="string">Display label (2-5 words)</ResponseField>
  <ResponseField name="level" type="integer">Hierarchy: 0=central, 1=core, 2=branch, 3=detail, 4+=deeper (used for layout)</ResponseField>
</Expandable>

<ResponseField name="edges" type="array">
  List of relationships between nodes. **Edges can connect nodes at any level** - not just parent-child hierarchies.
</ResponseField>

<Expandable title="edges[]">
  <ResponseField name="id" type="string">Edge ID</ResponseField>
  <ResponseField name="source" type="string">Source node ID</ResponseField>
  <ResponseField name="target" type="string">Target node ID (can be at any level)</ResponseField>
  <ResponseField name="relationship_type" type="string">Type: `contains`, `related`, `causal_positive`, `causal_negative`, `influences`</ResponseField>
</Expandable>

<Tip>
Node levels (0-4) are primarily for visual hierarchy and layout. Edges can freely connect nodes across different levels - for example, a level 4 detail node can connect to a level 2 branch node using `related` or `influences` relationship types.
</Tip>

<ResponseExample>
```json Basic Hierarchy

    {"id": "e3", "source": "core_nlp", "target": "branch_transformers", "relationship_type": "contains"}

  "metadata": {
    "created_by": "assistant"

}
```

# AI Tools

The AI has access to several built-in tools that execute automatically during chat.

## Available tools

### fetch_url

Fetches and extracts text content from webpages with automatic pagination for large pages.

**Parameters:**
- `url` (string, required) - Full URL including http:// or https://
- `chunk_index` (integer, default: 0) - Which chunk to retrieve (0-based)
- `chunk_size` (integer, default: 15000) - Characters per chunk

**Returns:**
- `content` - Extracted text content
- `title` - Page title
- `total_chunks` - Total chunks available
- `has_more` - Boolean indicating more chunks exist

**Example usage by AI:**
```json
// First call
{"url": "https://example.com/long-article", "chunk_index": 0}

// If has_more=true, fetch next chunk
{"url": "https://example.com/long-article", "chunk_index": 1}
```

### create_graph

Creates a new empty graph artifact.

**Parameters:**
- `title` (string) - Graph title
- `graph_type` (string) - One of: `mind_map`, `concept_map`, `causal_loop`, `systems_thinking`

**Returns:**
- `artifact_id` - ID of created artifact

### add_node

Adds a node to an existing graph.

**Parameters:**
- `artifact_id` (string) - Graph artifact ID
- `id` (string) - Descriptive node ID (e.g., 'central_ai', 'core_nlp')
- `label` (string) - Display label (2-5 words)
- `level` (integer) - Hierarchy: 0=central, 1=core, 2=branch, 3=detail

### add_edge

Connects two nodes with a relationship.

**Parameters:**
- `artifact_id` (string) - Graph artifact ID
- `source` (string) - Source node ID
- `target` (string) - Target node ID
- `relationship_type` (string) - Type: `contains`, `related`, `causal_positive`, `causal_negative`, `influences`

### finish_graph

Finalizes graph layout after adding all nodes and edges.

**Parameters:**
- `artifact_id` (string) - Graph artifact ID

### list_graphs

Lists all graph artifacts in the workspace.

# Troubleshooting

<AccordionGroup>
  <Accordion title="File search not working">
    **Symptoms:** No `file_search_call` events in chat responses
    
    **Solutions:**
    - Verify workspace has vector stores with uploaded files
    - Confirm `enable_file_search: true` in request (default)
    - Check file upload status is "completed"
    - Ensure question relates to document content
    - Try more specific search terms
  </Accordion>

  <Accordion title="URL fetching fails">
    **Symptoms:** `url_fetch_error` event or timeout
    
    **Solutions:**
    - Verify URL is accessible (not behind authentication)
    - Check URL returns HTML content (not JSON/XML APIs)
    - Some sites block bots - try alternative sources
    - Ensure URL includes http:// or https://
  </Accordion>

  <Accordion title="File upload errors">
    **Symptoms:** 400/500 errors on file upload
    
    **Solutions:**
    - Check file size is under 512MB
    - Verify file format is supported (see supported types)
    - Ensure text files are UTF-8, UTF-16, or ASCII
    - Try converting file to PDF if other formats fail
  </Accordion>

  <Accordion title="SSE stream disconnects">
    **Symptoms:** Stream stops mid-response
    
    **Solutions:**
    - Use `-N` flag with cURL (`curl -N`)
    - Disable buffering in HTTP clients
    - Check network stability
    - Implement reconnection logic with `since_id`
  </Accordion>

  <Accordion title="Annotations not appearing">
    **Symptoms:** No citations in AI responses
    
    **Solutions:**
    - Verify files are indexed (status="completed")
    - Check `file_search_call` events are occurring
    - Parse the `annotations` array in `content` events
    - Ensure questions require document references
  </Accordion>

  <Accordion title="Large webpages truncated">
    **Symptoms:** AI says "content truncated" or incomplete info
    
    **Solutions:**
    - AI should automatically fetch additional chunks
    - Check for `url_chunk_retrieved` events
    - Verify `has_more` field in fetch_url results
    - If AI doesn't paginate, prompt: "Can you fetch the remaining chunks?"
  </Accordion>
</AccordionGroup>

# Error codes

| Code | Description | Solution |
|------|-------------|----------|
| 400 | Bad request - invalid parameters | Check request format and required fields |
| 404 | Resource not found | Verify workspace/artifact/vector store ID |
| 422 | Validation error | Review parameter types and constraints |
| 500 | Server error | Check logs, retry request |
| 503 | OpenAI API unavailable | Wait and retry, check OpenAI status |

# Rate limits

No built-in rate limits. Implement rate limiting in your API gateway for production.

**Recommended limits:**
- 100 requests/minute per user
- 10 concurrent SSE connections per user
- 50 file uploads/hour per workspace
